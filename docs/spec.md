# StudyForge AI — MVP 仕様書

---

## 1. プロダクト概要

**StudyForge AI** は、日本語IT学習者がテキストや技術記事URLを入力すると、AIが重要ポイントを抽出してフラッシュカードと選択式クイズを自動生成する学習アプリである。

生成されたカードはユーザーが確認・編集してからデッキに保存し、フラッシュカード学習と選択式クイズで繰り返し学習できる。学習結果（覚えた／まだ苦手）は記録され、簡易的な学習履歴として確認できる。

---

## 2. 対象ユーザー

### プライマリユーザー

**自己学習するITエンジニア・学習者**

- Claude Code、Linux、Git/GitHub、Supabase、n8n、VPS 運用などを日本語で学んでいる
- 技術記事や公式ドキュメントを読んでも知識が定着しにくいと感じている
- 移動中・すき間時間にスマホで復習したい

### セカンダリユーザー（Phase 2 以降で想定）

- IT 講師・メンター（生徒用にデッキを作成・共有したい）
- 技術コミュニティ（公開デッキを購入・配布したい）

---

## 3. 解決する課題

| # | 課題 | 現状の代替手段 | StudyForge AI の解決策 |
|---|------|--------------|----------------------|
| 1 | 技術記事を読んだだけでは知識が定着しない | ノートに手書きメモ → 時間がかかる | 記事URLを貼るだけでカードを自動生成 |
| 2 | フラッシュカードを手動で作るのが面倒 | Anki に手動入力 → 作成コストが高い | AIが重要ポイントを抽出して生成 |
| 3 | 復習のタイミングが管理できない | カレンダーに手動設定 → 続かない | 学習履歴を記録して振り返れる |
| 4 | 英語コンテンツ中心の学習ツールが多い | DeepL 翻訳 + Anki → 手間が多い | 日本語出力に特化したプロンプト設計 |
| 5 | 読んだだけで理解できているか確認できない | 自分でテスト問題を作る → 難しい | AIが選択式クイズを自動生成 |

## 4. MVP で作る機能

### 機能一覧

| # | 機能 | 説明 |
|---|------|------|
| 1 | **テキスト入力** | テキストエリアに教材文を貼り付けてカードを生成 |
| 2 | **URL入力** | 技術記事のURLを入力してWebページ本文からカードを生成 |
| 3 | **AIによる重要ポイント抽出** | Claude API がテキストから学習価値の高い概念を選定 |
| 4 | **フラッシュカード生成** | 表面（問い）・裏面（答え）の形式でカードを生成（標準10枚） |
| 5 | **選択式クイズ生成** | フラッシュカードを元に4択クイズを生成（標準5問） |
| 6 | **生成結果の確認・編集** | 保存前にカードの表面・裏面を編集、不要なカードを削除 |
| 7 | **デッキ保存** | 確認・編集後のカードをデッキとしてDBに保存 |
| 8 | **復習画面（フラッシュカード）** | 1枚ずつめくりながら学習 |
| 9 | **覚えた / まだ苦手 の記録** | 各カードに「わかった」「もう一度」を記録 |
| 10 | **学習履歴の簡易表示** | デッキごとに正解率・学習済みカード数を表示 |

### 機能の詳細仕様

#### 機能 1: テキスト入力

- 入力可能文字数: 最大 8,000 文字
- 文字数カウンターをリアルタイム表示（残り文字数）
- 8,000 文字超過時: 送信ボタンを無効化してエラーメッセージ表示

#### 機能 2: URL入力

- `http://` または `https://` で始まる URL のみ受け付ける
- サーバーサイドで対象URLにフェッチしてHTML取得（タイムアウト: 10秒）
- `<main>`, `<article>`, `<p>` タグの順で本文テキストを優先抽出
- 抽出テキストを8,000文字に切り詰めてAIに渡す

#### 機能 3 & 4: フラッシュカード生成

- 生成枚数: **標準10枚**（変更不可、MVP では固定）
- デッキ名: AIが自動生成（ユーザーが後から編集可能）
- 1枚のカードには1概念のみ含める（粒度の細かいカードにする）
- 表面（front）: 問いの形式（「〜とは何ですか？」「〜の目的は？」）
- 裏面（back）: 200文字以内の明確な答え（箇条書き可）

#### 機能 5: 選択式クイズ生成

- 生成問題数: **標準5問**（変更不可、MVP では固定）
- デッキのカード情報（front/back）を基にAIが生成
- 形式: 4択選択式
- 誤答選択肢は「惜しい」ものを選ぶ（学習効果向上のため）
- クイズはデッキ保存後に初回アクセス時に自動生成してDBに保存

#### 機能 6: 生成結果の確認・編集

- 生成後、DBへの保存前に確認・編集画面を表示
- 各カードの表面・裏面をインラインテキスト入力で編集可能
- 個別カードの削除が可能
- 「やり直す」で入力画面に戻れる（生成結果は破棄）
- 保存前はセッションストレージに一時保持し、DBには書き込まない

#### 機能 7: デッキ保存

- 確認・編集後に「デッキに保存する」ボタンを押すとDBに保存
- 保存成功後、そのデッキの詳細ページに遷移

#### 機能 8: 復習画面（フラッシュカード）

- 1枚ずつカードを表示
- 表面が最初に表示される
- クリック/タップで裏面に反転（CSSフリップアニメーション）
- 進捗バー（例: 3 / 10）を上部に表示
- 全カード完了後にサマリー（正解率・「もう一度」ボタン）を表示

#### 機能 9: 覚えた / まだ苦手 の記録

- 裏面を表示した後に「わかった」「もう一度」ボタンを表示
- 「わかった」= `result: correct`, 「もう一度」= `result: incorrect` として `review_log` に記録
- クイズの回答も同様に `review_log` に記録

#### 機能 10: 学習履歴の簡易表示

- デッキ詳細ページにて以下を表示:
  - 総カード数
  - 直近の学習日時
  - 直近セッションの正解率（`review_log` 集計）
- 複雑なスペーシングアルゴリズムは MVP に含めない

## 5. MVP で作らない機能

| 機能 | 理由 |
|------|------|
| PDF アップロード | ファイル処理・テキスト抽出の実装コストが高い |
| YouTube 解析 | 字幕API連携・音声文字起こし連携が必要 |
| Anki エクスポート | `.apkg` フォーマット生成ライブラリの調査が必要 |
| 課金・デッキ販売 | Stripe 連携・販売フローが複雑。データ蓄積後に検討 |
| チーム機能 | マルチテナント設計が必要。ユーザー需要の確認が先 |
| SNS 共有 | デッキ公開機能（`is_public`）の先にある機能 |
| 複雑な間隔反復アルゴリズム（SM-2 等） | `review_log` のデータが蓄積してから実装する |
| 学習リマインダー（メール・プッシュ通知） | 通知インフラが必要 |
| モバイルアプリ（iOS/Android） | PWA/レスポンシブWebで代替。需要確認後に検討 |

## 7. ユーザーフロー

### フロー A: 新規ユーザーが初めてカードを作って学ぶ

```
1. `/` でサービス概要を確認
2. 「はじめる（無料）」→ `/auth/signup` で登録
3. 確認メールのリンクをクリック → セッション確立
4. `/generate` でテキスト or URL を入力して「生成する」
5. ローディング（約5〜15秒）
6. `/generate/review` で生成結果を確認・必要なら編集
7. 「デッキに保存する」→ `/decks/[id]` へ遷移
8. 「学習する」→ `/decks/[id]/study` でフラッシュカード学習
9. 「わかった」「もう一度」を押しながら10枚を学習
10. サマリー画面で正解率を確認
11. 「小テスト」→ `/decks/[id]/quiz` で5問チャレンジ
12. 結果確認 → `/decks/[id]` に戻る
```

### フロー B: 既存ユーザーが復習する

```
1. `/` にアクセス（自動ログイン）
2. ダッシュボードのデッキ一覧から復習したいデッキを選ぶ
3. `/decks/[id]` で学習履歴（正解率・前回学習日）を確認
4. 「学習する」または「小テスト」で学習開始
5. 結果を記録して終了
```

### フロー C: URLからカードを生成する

```
1. ブラウザで技術記事を開く
2. URLをコピー
3. `/generate` の「URL入力」タブにURLを貼り付け
4. 「生成する」→ サーバー側でHTMLをフェッチしてAI処理
5. フロー A の 6 以降と同じ
```

## 8. データ要件

### 8-1. テーブル設計

#### `deck`（デッキ）

| カラム | 型 | 制約 | 説明 |
|--------|----|------|------|
| `id` | `uuid` | PK, default gen | デッキID |
| `user_id` | `uuid` | FK → `auth.users.id`, NOT NULL | オーナー |
| `name` | `text` | NOT NULL | デッキ名 |

| `created_at` | `timestamptz` | NOT NULL, default now() | 作成日時 |
| `updated_at` | `timestamptz` | NOT NULL, default now() | 更新日時 |

#### `card`（フラッシュカード）

| カラム | 型 | 制約 | 説明 |
|--------|----|------|------|
| `id` | `uuid` | PK, default gen | カードID |
| `deck_id` | `uuid` | FK → `deck.id` ON DELETE CASCADE, NOT NULL | 所属デッキ |
| `front` | `text` | NOT NULL | 表面（問い） |
| `back` | `text` | NOT NULL | 裏面（答え） |
| `position` | `integer` | NOT NULL, default 0 | 表示順 |
| `created_at` | `timestamptz` | NOT NULL, default now() | 作成日時 |
| `updated_at` | `timestamptz` | NOT NULL, default now() | 更新日時 |

#### `quiz`（選択式クイズ問題）

| カラム | 型 | 制約 | 説明 |
|--------|----|------|------|
| `id` | `uuid` | PK, default gen | 問題ID |
| `deck_id` | `uuid` | FK → `deck.id` ON DELETE CASCADE, NOT NULL | 所属デッキ |
| `question` | `text` | NOT NULL | 問題文 |
| `choices` | `text[]` | NOT NULL, array length = 4 | 選択肢（4つ） |
| `answer_index` | `integer` | NOT NULL, 0〜3 | 正解インデックス |
| `created_at` | `timestamptz` | NOT NULL, default now() | 作成日時 |

#### `review_log`（学習履歴）

| カラム | 型 | 制約 | 説明 |
|--------|----|------|------|
| `id` | `uuid` | PK, default gen | ログID |
| `user_id` | `uuid` | FK → `auth.users.id`, NOT NULL | ユーザー |
| `card_id` | `uuid` | FK → `card.id` ON DELETE CASCADE, NOT NULL | 対象カード |
| `result` | `text` | NOT NULL, check in ('correct','incorrect') | 結果 |
| `study_mode` | `text` | NOT NULL, check in ('flashcard','quiz') | 学習モード |
| `reviewed_at` | `timestamptz` | NOT NULL, default now() | 学習日時 |

### 8-2. ER 図

```
auth.users
    │
    ├─── deck (user_id)
    │        │
    │        ├─── card (deck_id)
    │        │        │
    │        │        └─── review_log (card_id)  ←── auth.users (user_id)
    │        │
    │        └─── quiz (deck_id)
    │
    └─── review_log (user_id)
```

### 8-3. RLS 方針

| テーブル | SELECT | INSERT | UPDATE | DELETE |
|----------|--------|--------|--------|--------|
| `deck` | `user_id = auth.uid()` OR `is_public = true` | `user_id = auth.uid()` | `user_id = auth.uid()` | `user_id = auth.uid()` |
| `card` | deck 経由で `user_id = auth.uid()` | 同左 | 同左 | 同左 |
| `quiz` | deck 経由で `user_id = auth.uid()` | 同左 | 不可 | 同左 |
| `review_log` | `user_id = auth.uid()` | `user_id = auth.uid()` | **不可** | **不可** |

`review_log` は追記専用。過去の学習記録は改ざんさせない。

### 8-4. 制約・データ整合性

- デッキを削除すると `card`, `quiz`, `review_log` が CASCADE 削除される
- カードを削除すると紐づく `review_log` が CASCADE 削除される
- `card.position` は 0 始まりの連番。デッキ内でユニークである必要はない（並び替えのみに使用）

## 9. AI 生成要件

### 9-1. 対象ジャンル

以下のジャンルで学習品質の高いカードを生成できることを優先する:

- Claude Code（AIエージェント・プロンプト・Claude API）
- Linux（コマンド操作・シェルスクリプト・ファイルシステム）
- Git / GitHub（バージョン管理・ブランチ戦略・Pull Request）
- Supabase（PostgreSQL・Auth・RLS・Storage・Edge Functions）
- n8n（ワークフロー自動化・ノード設定・API連携）
- VPS 運用（サーバー設定・Nginx・SSH・セキュリティ）

### 9-2. フラッシュカード生成プロンプト要件

**入力**: テキスト（最大 8,000 文字）、生成枚数（標準: 10）

**出力形式（JSON のみ）**:
```json
{
  "deckName": "Supabase RLS 入門",
  "cards": [
    {
      "front": "RLS（Row Level Security）とは何ですか？",
      "back": "テーブルの各行に対してアクセス制御ポリシーを定義できるPostgreSQLの機能。ユーザーごとに読み書き可能な行を制限できる。"
    }
  ]
}
```

**プロンプト設計方針**:
- System プロンプトで出力形式（JSON）と生成ルールを厳密に指定
- JSON 以外の説明文・コードフェンスを含めないよう明示する
- 1枚のカードには1概念のみ（複数の概念を1枚に詰め込まない）
- 表面（front）は問いの形式（「〜とは何ですか？」「〜の役割は？」「〜するにはどうしますか？」）
- 裏面（back）は200文字以内、日本語で自然な文体、箇条書き可
- 重要度の高い概念から優先的に選ぶ
- デッキ名はテキストの主題を反映した簡潔な日本語（〜入門、〜完全ガイドなど）

**バリデーション**:
- AIのレスポンスが有効なJSON でない場合: リトライを1回行い、それでも失敗したらエラーを返す
- `cards` 配列が空の場合: エラーとして扱う
- 生成枚数が指定より少ない場合: そのまま使用する（エラーとしない）

### 9-3. 選択式クイズ生成プロンプト要件

**入力**: デッキのカード一覧（front/back）、生成問題数（標準: 5）

**出力形式（JSON のみ）**:
```json
{
  "quizzes": [
    {
      "question": "SupabaseのRLSを有効にするSQLコマンドはどれですか？",
      "choices": [
        "ALTER TABLE deck ENABLE ROW LEVEL SECURITY;",
        "SET ROW SECURITY ON deck;",
        "GRANT RLS TO deck;",
        "ENABLE POLICY ON deck;"
      ],
      "answer_index": 0
    }
  ]
}
```

**プロンプト設計方針**:
- 問題はカードの `back`（答え）の内容を問う形式にする
- 誤答選択肢は「惜しい・紛らわしい」内容にして学習効果を高める
- 正解インデックスはランダムに分散させる（全問 0 番が正解にならないよう指示）
- 重複する問題は生成しない

### 9-4. 使用モデル

- `claude-sonnet-4-6`（コスト・品質のバランスが最適）
- `max_tokens`: カード生成 2,000 / クイズ生成 1,500
- `temperature`: 指定なし（デフォルト）

## 10. エラー時の挙動

### API エラー一覧

| シナリオ | HTTPステータス | ユーザーへのメッセージ |
|----------|--------------|---------------------|
| テキストが 8,000 文字超過 | 400 | 「テキストが長すぎます。8,000文字以内に収めてください。」 |
| URL が `http/https` 以外 | 400 | 「有効な URL を入力してください（http または https で始まるURL）。」 |
| URL フェッチがタイムアウト（10秒超過） | 504 | 「URLからの情報取得がタイムアウトしました。テキスト入力をお試しください。」 |
| URL フェッチ失敗（404・接続エラー等） | 502 | 「URLにアクセスできませんでした。URLを確認するか、テキスト入力をお試しください。」 |
| 本文テキストを抽出できない | 422 | 「このページからテキストを取得できませんでした。テキスト入力をお試しください。」 |
| AI 生成失敗（Anthropic API エラー） | 502 | 「カードの生成に失敗しました。しばらく待ってからもう一度お試しください。」 |
| AI 生成結果が無効な JSON | 502 | 「カードの生成に失敗しました。もう一度お試しください。」 |
| 未認証でAPIを呼び出し | 401 | 「セッションが切れました。再度ログインしてください。」（ログインページへリダイレクト） |
| DB 保存失敗 | 500 | 「保存に失敗しました。もう一度お試しください。」 |

### UX でのエラー表示方針

- API エラーは画面上部の **トースト通知**（`shadcn/ui` の Toast）で表示する
- 入力バリデーションエラーは **インライン**（フォームフィールドの下）に表示する
- トースト通知は自動で5秒後に消える。エラーは消えない（手動で閉じる）
- ネットワーク系エラー（タイムアウト等）は「テキスト入力をお試しください」に誘導する
- 500 系エラーは具体的な原因をユーザーに見せない（ログはサーバーに記録）

## 11. 受け入れ条件

MVP のリリース判定に使用するチェックリスト。

### 認証

- [ ] メールアドレスとパスワードで新規登録できる
- [ ] 確認メールのリンクでメール確認が完了できる
- [ ] ログイン・ログアウトが正常に動作する
- [ ] 未ログイン状態で `/generate`, `/decks` にアクセスするとログインページに遷移する

### カード生成（テキスト入力）

- [ ] 8,000 文字以内のテキストを入力して「生成する」を押すとカードが生成される
- [ ] 生成中はローディング表示が出る
- [ ] 生成結果として 10 枚（またはそれ以下）のカードが表示される
- [ ] カードの表面は問いの形式、裏面は答えの形式になっている
- [ ] 8,001 文字以上入力すると送信できずエラーメッセージが表示される

### カード生成（URL入力）

- [ ] 有効な https URL を入力して「生成する」を押すとカードが生成される
